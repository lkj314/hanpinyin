# HanPinyin 原始设计方案（用户提供的设计底稿）

> 用途：作为 PM 的 PRD 与 Architect 架构设计的输入底稿。本文为原样保存的用户设计文档。

## 1. 项目背景与目标

### 1.1 背景
- 大量中国玩家在韩服《英雄联盟》中因不熟悉韩语键盘布局而无法快速交流。
- 现有韩语输入法（두벌식）需记忆键位映射，学习成本高。
- 玩家熟悉汉语拼音，且拼音本身具有语义（知道“wan le”意为“完了”）。

### 1.2 目标
开发一款轻量级输入工具，用户输入汉语拼音串（如 wan le yi xia wu），实时转换为韩语文本（如 오후 내내 했어），并支持候选词选择与快捷发送。

## 2. 功能需求

| ID | 功能 | 描述 |
|----|------|------|
| F1 | 拼音→韩语转换 | 输入完整拼音或首字母缩写，输出对应韩语 |
| F2 | 多候选词 | 同一拼音对应多个韩语词时，展示候选列表（数字键选择） |
| F3 | 模糊拼音 | 支持 zh/z、ch/c、sh/s、an/ang 等常见模糊音 |
| F4 | 整句输入 | 连续输入拼音串，自动分词并匹配最佳组合 |
| F5 | 常用短语库 | 预置约200条韩服游戏常用语（如“gg”、“tank”、“carry”） |
| F6 | 用户词库 | 记录用户历史选择，优先显示高频词 |
| F7 | 快捷发送 | 选中后自动模拟 Ctrl+V 或 SendInput 将文本发送至当前激活窗口 |
| F8 | 悬浮窗 UI | 跟随光标的小窗口显示候选词，支持鼠标点击或数字键选择 |

## 3. 非功能需求
- 响应速度：从输入完成到显示候选 < 50ms（本地词典，无网络依赖）。
- 内存占用：< 20MB（含词库）。
- 兼容性：Windows 10/11，支持 DirectInput 游戏窗口（需使用 SendInput 而非剪贴板）。
- 可扩展：词库采用 JSON 或 SQLite 格式，用户可自行增删。

## 5. 模块设计

### 5.1 键盘钩子模块
- 使用 SetWindowsHookEx(WH_KEYBOARD_LL) 监听全局按键。
- 检测到用户按下 Ctrl+Space 切换输入法状态。
- 进入输入模式后，拦截字母键和数字键，其余按键透传。
- 空格键触发“确认当前拼音串并开始匹配”；退格键删除最后一个拼音音节。

### 5.2 拼音解析引擎
- 拼音音节分割：根据汉语拼音规则（声母+韵母）将连续字母串分割为音节列表。例如 wanleyixiawu → [wan, le, yi, xia, wu]。
- 模糊音归一化：将 zh→z, ch→c, sh→s, ing→in 等映射到标准形式，提高容错。
- 查询方式：使用 Trie 树存储拼音→韩语映射，支持前缀匹配。

### 5.3 候选词管理器
- 对于单音节拼音，返回所有匹配词（如 wan → 완, wan → 왕）。
- 对于多音节组合，使用动态规划寻找最优路径（基于词频+上下文权重）。
- 候选列表按词频降序排列，用户选择后更新词频。

### 5.4 悬浮窗 UI
- 使用 Win32 API 创建无边框透明窗口，采用 Direct2D 渲染文字。
- 窗口位置跟随鼠标光标或输入光标（通过 GetCaretPos 获取）。
- 显示最多 5 个候选词，编号 1~5，支持鼠标悬停高亮。
- 用户可按数字键 1~5 选择，或按 Tab 翻页。

### 5.5 文本发送器
- 用户选定候选词后，调用 SendInput 模拟按键序列：先 Ctrl+A 全选当前输入框内容，再 Delete 删除，最后 SendInput 发送韩语字符串。
- 若游戏不支持 Unicode 输入，则使用剪贴板方式：OpenClipboard → SetClipboardData(CF_UNICODETEXT) → Ctrl+V。

## 6. 数据结构

### 6.1 拼音→韩语映射表（主词库）
```
struct PinyinEntry {
    std::string pinyin;          // 归一化后的拼音，如 "wan"
    std::vector<std::pair<std::wstring, int>> candidates; // 韩语字符串, 初始频率
};
```
- 使用 std::unordered_map<std::string, PinyinEntry> 或 Trie 树。
- 预置约 3000 条常用词（包括韩服游戏术语、日常用语、英雄名称等）。

### 6.2 用户词库
- 保存于 user_dict.json，格式：
```
{
  "wan": [["완", 5], ["왕", 2]],
  "wan le": [["완료", 3]]
}
```
- 启动时加载，退出时保存。

### 6.3 短语库（固定常用语）
- 硬编码在代码中或单独 phrases.json，每条包含拼音和韩语，如：
```
{ "pinyin": "wan le yi xia wu", "korean": "오후 내내 했어" }
```

## 7. 算法关键点

### 7.1 拼音音节分割
- 正向最大匹配：从字符串头部尝试最长合法拼音（如 wan 合法，则切出 wan，剩余继续）。
- 备选：基于有限状态机（FSM）识别声母+韵母组合。

### 7.2 多音节最优组合
- 使用 Viterbi 算法：定义状态为当前位置，转移代价为词频负对数，选择概率最大的词序列。
- 示例：输入 wo jue de ying le，计算最佳路径得到 나는 이겼다고 생각해.

## 8. 用户界面设计
- 主界面：极小悬浮条，宽 300px，高 30px，半透明背景。
- 候选区：显示 1~5 项，每项格式：“1. 韩语 (拼音原文)”，例如 1. 안녕하세요 (ni hao)
- 状态指示：左侧显示当前输入模式图标（🔤 拼音模式 / 🈳 关闭）。
- 交互：鼠标点击或数字键选择；Esc 取消输入；Enter 直接发送首个候选。

## 10. 风险与应对
- 风险：部分游戏（如韩服LOL）可能屏蔽 SendInput 或钩子。
  - 应对：提供剪贴板+Ctrl+V 后备方案；使用 WH_KEYBOARD_LL 低级别钩子通常不被反作弊封禁。
- 风险：拼音歧义导致转换错误。
  - 应对：提供候选列表让用户选择，并利用用户词库逐步优化。
